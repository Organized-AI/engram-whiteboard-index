// GUIDE — full video walkthrough

The talk is broader than just Engram. It's a walkthrough of the full memory hierarchy an LLM inference system runs on — VRAM, DRAM, NVMe, and how a model's weights move across them — with one specific segment describing something that matches Engram's mechanism almost exactly. This guide walks through what was actually said, in order, and marks where the diagram above maps to spoken content versus where it doesn't.

[00:00–00:28] Storage and system memory

Opens by placing NVMe on a CPU-side bus, then adds DRAM as the system's main memory. Establishes that CPU, DRAM, and NVMe are parts of one physical machine, not separate services.

[00:28–00:56] GPU and VRAM

VRAM is framed as fast but constrained — the tier where a model actually executes, in contrast to larger and slower DRAM/NVMe.

[00:56–01:21] First request, full load

On a first API request, the model generally has to be loaded in full — ideally into VRAM if it fits, otherwise into DRAM. Model size relative to available VRAM is the operational constraint.

[01:21–01:49] The 96GB constraint and spillover

This is where 96GB VRAM on the diagram comes from directly — his own Grace Hopper system, contrasted with a consumer 4090 card. If the model exceeds available VRAM, layers "spill" into DRAM and get pulled back as needed. Capacity-vs-speed tradeoff: it still runs, just slower across tiers.

[01:49–02:14] Model internals: MoE and routing

Zooms from hardware into model structure — Mixture-of-Experts layers, expert routing, selective attention. Not every part of the model needs to be active for every input.

ENGRAM MATCH

[02:14–02:40] Static pattern offload

This is the part that's actually Engram. The example given: early layers handle simple, stereotyped associations — "New York," where "New" and "York" are a near-fixed pairing — and because that's cheap, static pattern-matching rather than real reasoning, those layers don't need to sit in scarce, expensive VRAM. They can live in slower memory, addressed by a pointer, freeing VRAM for the layers that actually benefit from it. That's the same shape as Engram's core claim: separate static knowledge lookup from dynamic reasoning, offload the former, keep the latter where compute is fast.

[02:40–02:58] Clarification

Confirms all of this — CPU, GPU, VRAM, DRAM, NVMe — is one physical box, not a distributed system.

[02:58–03:47] Grace Hopper specifics

Names his own setup as Grace Hopper: 96GB VRAM for GPU work, CPU and GPU portions linked by NVLink. An interconnect speed is mentioned but the unit in the audio isn't clear (roughly "680 megabits or gigabits") — treat that number as approximate.

[03:47–04:10] Comparison to a 4090 PC

Grace Hopper (96GB VRAM, tight interconnect) vs. a 4090 setup (~36GB VRAM, ~64GB DRAM, separate NVMe). Argument: total capacity isn't the whole story — where the model sits and how fast each tier feeds the GPU matters just as much.

[04:10–04:20] Apple unified memory

Closing comparison: Apple's unified memory merges the VRAM/DRAM split into one shared pool, removing that hard separation (though not automatically uniform speed or unlimited capacity).
